# IF 本地 AI 模拟交易台

实时 IF 行情、本地信号与Luna审核、本地模拟成交、独立程序风控和收盘复盘。行情服务只读取市场数据，全部委托、成交和资金记录保存在本机模拟账本。

## 启动与停止

双击 Start-Futures.cmd，或在 PowerShell 中运行：

    .\Start-Futures.ps1

交易台地址：http://127.0.0.1:8765/ 。启动器等待服务就绪后打开浏览器，已有服务时直接打开。

- 启动自动模拟：交易时段行情有效时，每1分钟在本地检查规则；仅有可开仓信号或持仓反向平仓信号才请Luna审核，无信号不调用模型。审核只能选择候选动作或观望，单次请求不重叠；同一合约、策略版本、已完成1分钟K线、动作和持仓的信号不重复送审（重启后仍保留去重）。审核失败或被否决后，下一根K线仍有信号才再次送审；返回后重查信号，已经变化则不执行。页面刷新只读取本地状态，程序风控独立运行。
- 暂停开仓：暂停AI自动交易；已有仓位的程序止损、止盈和保证金检查继续。
- 立即分析：手动请求Luna分析，不受自动信号筛选限制，可能产生模型费用；休市时可阅读判断，旧报价不会产生模拟成交。
- 生成复盘：汇总当日记录，随后检查策略候选。
- 平仓：按持仓真实合约的新鲜可成交盘口模拟成交，没有条件时等待。

关闭浏览器后服务继续运行。退出程序请双击 Stop-Futures.cmd，或运行 Stop-Futures.ps1，保存状态后结束行情进程。持仓在下次启动恢复。电脑停机、休眠或断网期间无法处理市场变化，复市跳空可能使损失超过计划值。

直接运行开发服务：

    .\.venv\Scripts\python.exe -X utf8 -m futures_app
    .\.venv\Scripts\python.exe -X utf8 -m futures_app --no-auto-start

## 已确认的账户和风控

配置在 config.json；持久账本在 data/futures.sqlite3。重启不重置余额和当日亏损锁。

| 项目 | 首版设置 |
| --- | --- |
| 品种 | IF 沪深300股指期货，从主连映射到真实月份合约 |
| 初始资金 | 100万元 |
| 最大持仓 | 1手，不同时持有多空，不支持半手 |
| 单笔计划风险 | 5000元，含估计进出费用、价差及止损滑点；超限拒绝开仓 |
| 当日停止开仓线 | 含浮亏和费用的当日亏损达2万元；日内恢复盈利也不解除 |
| 隔夜和休市 | 允许隔夜、跨周末和长假，由AI综合评估 |
| 跟踪止损 | 向盈利方向运行达初始止损距离的1倍后，按该距离跟踪最有利价格，只收紧 |
| 到期保护 | 依据真实expire_datetime，前24小时停止开仓，前60分钟尝试平旧仓，不直接改仓位代码 |

Luna不能放宽程序限制。程序保护独立于模型请求：模型超时、预算不足或开仓暂停时仍运行。保护触发后没有成交条件，会记录待退出状态并等待后续有效盘口。

若停机跨过合约到期或到期前始终无法成交，会标记等待官方最终结算价，不伪造现金交割、不清零或移仓。这类异常需补充官方最终结算价处理。

跨日结算在下一有效交易日首条报价时执行，优先采用持仓合约的前结算价；缺失时用上一已观察行情估值并标注非官方假设。现金和浮盈亏重新划分不重复计收益，新开盘跳空计入当日盈亏。

## 明确标注的保守成本

以下均为 conservative-v1 项目假设，用于偏保守地评估策略，不代表交易所或期货公司的实际收费：

| 项目 | 假设 |
| --- | --- |
| 开仓手续费 | 成交金额 × 0.005% |
| 当天开仓当天平仓手续费 | 成交金额 × 0.05% |
| 历史仓位平仓手续费 | 成交金额 × 0.005% |
| 附加佣金 | 每手每边20元 |
| 额外滑点 | 每边2个最小价位，即0.4点，IF对应每边120元 |
| 保证金占用 | 合约价值的20%，只占用资金，不作为费用扣除 |

买入参考卖一再加不利滑点，卖出参考买一再减不利滑点；买卖价差已体现在成交价中，不重复收费。盘口、可成交量、涨跌停、限价、新鲜度和合约检查通过后才成交。跳空止损按触发后首个可成交盘口处理，不能保证计划止损价。

每笔保留成本版本，展示手续费、佣金及整笔平仓净盈亏。开仓记录只示开仓费用，避免汇总重复扣费。成本缺失不按零处理，Luna不能通过降低成本假设改善成绩。候选和基准使用相同成本口径，配置变更不覆盖历史账本或已有持仓的成本版本。

## 策略和持续迭代

默认5分钟快/慢均线8/21判断方向，1分钟回调找入场，ATR窗口14、初始止损1.8倍ATR、目标收益风险比2。只使用已完成K线。规则信号经Luna结合账户和风险复核后，仍须通过本地风控与成交检查。

Luna负责信号审核和收盘复盘中的规则改进建议；无信号时不做定时持仓AI评估，已有持仓仍执行程序止损、止盈和保证金保护。收盘复盘与候选生成仍会调用模型。改进仅限白名单策略参数，须经过以下验证后才能启用，不能直接修改风险限制或费用。

策略和经验保存在本地，API调用不会自行训练Luna权重。

1. 收盘复盘记录真实交易，候选只能在白名单范围内提出少量参数变更。
2. 按时间分割训练和验证数据，候选提出时看不到留出区间。
3. 用相同费用、滑点和风险口径比较候选及当前规则基线。
4. 历史独立验证双方至少各10笔闭合交易达标后，进入真实未来行情的影子对照。
5. 影子对照至少3个交易日、双方各10笔，候选净收益为正、比基准至少多100元且回撤不劣于基准，才切换新开仓版本。
6. 后续样本明显退化时回退，保留旧版本；已有仓位继续使用开仓版本和保护计划。

分钟回放无法还原完整盘口及盘内路径，使用明确标注的保守价差和滑点假设；同柱双触发先按止损。影子评估确定性规则及参数，不等同于证明未来每次AI判断都有效。样本不足保留原版，不降低门槛来制造升级。

## 时段、数据和模型

- IF连续交易时段：北京时间09:30–11:30、13:00–15:00，无夜盘；首版不参与集合竞价。
- calendar.json覆盖已核对的2026年休市安排，周末补班也不开市；覆盖年份之外暂停开仓，待公开日历更新。
- TqSdk提供真实行情，默认2400根1分钟和600根5分钟K线。行情进程独立运行，断线自动重连，缓存明确标注且不能用于成交。
- 首版未接入新闻或宏观事件源，AI收到事件信息未知提示，不能将缺少新闻当作没有事件风险。
- gpt-6-luna，标准处理、低推理强度，每次最多2048输出token。
- 每天2美元预算覆盖分析、复盘及候选生成，原子预留防并发超支；未知实际消耗的失败请求保留预留。
- 15:10起自动复盘，每日成功一份后停止自动生成；失败最多自动尝试3次，间隔至少5分钟，可手动重试。
- 用量仅指本程序账本，按核实的未缓存标准价保守估计；平台账单为准，早期连接诊断不在应用用量内。

更换模型时核对config.json中的模型、对应价格与接口权限，再重启。账户、持仓、订单、版本和开仓理由保留。价格未知或与配置不一致时暂停调用。

## 凭据与备份

快期账号及项目API密钥由当前Windows用户的DPAPI加密，存于.local/secrets.dpapi。网页不返回凭据，服务仅监听127.0.0.1，写操作校验同源与CSRF。敏感目录及账本已忽略版本控制。

重新配置：

    .\.venv\Scripts\python.exe -m futures_probe setup --stage market
    .\.venv\Scripts\python.exe -m futures_probe setup --stage model

环境为Python3.12，依赖见requirements.lock.txt。备份时先停止程序，再备份整个data目录。DPAPI文件需相应Windows用户解密。
